# 规则与配置专题契约

域级 `configuration.md` 定义改变行为的业务规则、配置来源、优先级和分支。不局限于远端开关：固定限制、用户偏好、环境参数、实验、版本与能力条件都按实际机制说明。项目工程规范归 Team Standard，规则不因出现于源码就成为团队政策。

## 规则与决策

以业务条件或配置族命名条目。说明适用范围、事实来源、检查方、输入、判定顺序、短路和例外，以及允许、拒绝或回退的结果。区分当前事实、明确约束、归纳约定、待确认事项；固定规则不伪造配置键。

| 条件组合 | 顺序与优先级 | 行为分支 | 已发生副作用 | 例外/回退 | 验证 |
| --- | --- | --- | --- | --- | --- |

多条件用决策表；检查相对写入、加锁、调用外部系统的顺序会改变结果时补流程说明。

## 配置身份与生效

| 信息 | 需要查明 |
| --- | --- |
| 身份 | 精确键、参数名、常量或业务别名；普通配置、用户偏好还是实验 |
| 值与来源 | 类型、单位、合法值、默认值、来源与覆盖顺序；缺失或畸形值的回退 |
| 消费方 | 真实读取者、判定者及影响的功能，不以声明位置代替消费位置 |
| 时机 | 每次读取、启动或实例创建时冻结、缓存、订阅更新、重启/重建生效 |
| 组合 | 环境、平台、版本、身份、入口及其他条件；说明优先级和短路 |
| 观测 | 读取、命中或使用时如何观察；有实验曝光时说明时机和去重，事件详情引用生命周期专题 |
| 变更 | 动态更新、关闭、权限变化后的结果和安全回退；影响范围与验证入口 |

键和协议标识保持精确以便检索，不写入真实用户值、凭据或签名地址。不存在配置机制时说明已核验的规则和边界，不编造配置中心。

## 区分三种结论

- **源码条件**：某版本允许哪些分支，不证明线上已经启用。
- **配置快照**：带环境、版本、观察时间和适用范围，不成为永久真值。
- **运行事实**：实例真正读到什么并执行了什么；下发不证明缓存已更新或组合条件满足。

仅有源码时说明判定条件和验证方法，不能宣称当前命中。完成标准：读者能预测条件变化后的行为，找到实际读值和生效时机，并区分静态可能性与已观察结果。
