# 分类来源对照与范围确认

本指南仅在用户提供分类树、模块表或明确源码候选时使用。材料提供历史身份和覆盖线索，源码提供实际责任；两者不互相替代。不要从维护表的团队分组、代码目录或高连接度节点直接决定业务域。

## 先比较三种信息

| 来源 | 保留什么 | 不能直接推导什么 |
| --- | --- | --- |
| 已维护分类树 | 原始ID、名称、父链、平台声明和历史归属 | 层级不必等于本项目Domain/Module；大小写不自动重写 |
| 模块维护表 | 本轮授权的分类列、原始行定位、表/视图和读取范围 | 不按人员归属分域，不默认纳入更细层级，不把总行数当视图筛选数 |
| 当前源码 | 入口、业务结果、状态/数据所有权、实际调用与原生/共享分工 | 路径、同名符号、生成绑定或调用次数不能独立证明业务边界 |

先用稳定身份核对，再用同域精确名称或显式别名建立对应。语义相近但责任不同的条目保留冲突；同名跨域不自动合并。跨端实现可以属于同一能力，但语言和生成物不是新的业务模块。共享输入、路由、选图器、传输层等按独立责任判断，不随调用方的组织标签合并。

子项保留原身份和父链，默认作为场景候选；已经独立维护的子模块不能被静默删掉。提升或保留为正式模块需要明确映射及责任说明。历史平台默认只来自材料契约，不继承父节点，也不能补入未经声明的平台。

## 可选只读对照入口

`modus knowledge scope-compare --root <项目根> --input <清单.json> --json`

只读取显式文件，不扫描仓库、不联网、不构图、不写执行卡或知识。清单和材料默认在项目内；项目外读取根由调用者通过 `--allow-root <材料目录>` 显式授权，清单内容不能自行授权。所有相对路径相对项目根，不相对清单目录。

清单版本为1，可包含：

```json
{
  "schemaVersion": 1,
  "sources": [
    {"id": "taxonomy", "format": "mindmap", "path": "materials/map.md", "startMarker": "<!-- BEGIN_MODULES -->", "endMarker": "<!-- END_MODULES -->"},
    {"id": "inventory", "format": "csv", "path": "materials/modules.csv", "columns": {"group": "业务", "label": "一级模块"}}
  ],
  "candidates": [
    {"scopeRef": "module:export/document", "label": "文档导出", "reason": "源码调查得到的职责候选", "locations": [{"path": "src/export.py", "symbol": "export_document", "startLine": 1, "endLine": 5}]}
  ],
  "mappings": [
    {"sourceId": "inventory", "recordId": "row:2", "scopeRefs": ["module:export/document"], "reason": "维护名称与既有模块不同，需回查职责后确认"}
  ]
}
```

- `mindmap` 只支持此处约定的 Markdown：`## N. 名称 domain-id`、`### module-id 名称`、单层 `- child-id 名称：说明`。可用成对标记限定有效区间，避免把维护说明或协议参考当模块；不声称兼容任意思维导图文件。节点记录ID为 `node:<原ID>`。
- 平台后缀为 `[platform=ios,android]` 等原始值。需要来源默认平台时显式设置 `defaultPlatforms`；不传则未声明。默认值不沿树继承。
- CSV/XLSX 必须指定 `columns.group` 和 `columns.label`，可选 `columns.id`。重复表头、空分类行或重复ID报告错误，不自动向下填充。只输出指定列，其他列不进入比较结果。无记录ID时使用实际 `row:<行号>`；有ID时使用 `id:<原值>`。
- XLSX 还需指定 `sheet`，并由使用者显式安装 `openmodus[materials]`；程序不自动安装依赖。公式不执行，选中分类列含公式时拒绝，不使用公式缓存值。来源文件最大4 MiB、全部分类记录最多5000条，工作簿解压、行列数另有限制。
- 在线表通过用户授权的外部工具导出后再导入，不内置具体站点。可在来源 `provenance` 记录 `title/table/view/observedAt/coverage`；原始文件摘要绑定本次读取内容，不证明在线视图仍然相同。源不可读时保留缺口，不能用上次的总数冒充当前读取结果。
- `candidates` 是作者基于源码提出的范围，不是程序自动发现。程序只校验路径可读、行范围及摘要；符号和业务语义仍须回源判断。不存在代码候选时只能声称材料对照，不能声称三方融合完成。
- `mappings` 按来源记录限定，表达显式别名、移动/合并或拆分建议。目标必须已在分类树或候选中声明；多个目标必须说明职责划分。映射不是人工确认，输出仍须审阅。

`status: ok` 表示读取对照成功，不代表业务范围已确认；`partial` 和退出码4表示有不可用材料或源码定位；无匹配和冲突留在逐条结果，不当成不存在。纯候选的域/模块大小写冲突也在 `identityConflicts` 中列出。依赖不可用来源而无法核实记录或目标的映射保留在 `deferredMappings`，对应可读记录维持 `pending`，恢复来源后重新对照，不回退到名称匹配。未知来源、可读来源中的未知记录、重复映射和非法Scope仍报告输入错误。不得把排除、基础设施或平台能力伪造成正式模块来消除未决项。

## 合入唯一执行卡

对照结果含 `sourceReview`，所有条目初始都是 `pending`。根作者将它合入现有 `modus.authoring.sourceReview`，保留原卡的 domains、evidence、coverage、visuals 和进度，不重建较小执行卡，也不新建确认账本。旧执行卡无该字段时仍兼容；本轮明确使用分类材料时应记录，不能通过省略字段逃避处置。执行卡独立预算为整卡16 MiB、YAML解析及别名展开各200000节点，深度仍限64；5000条来源处置与原计划共享该总预算，超限须精简重复说明而不能删减来源清单。普通SKILL文档的解析预算不变。

与原 Scope 一次确认同时评审每条记录：正式归属写 `formal` 及本轮计划内的 `scopeRefs`；平台能力、基础设施、排除分别用 `platform/infrastructure/excluded`，写清落点或排除理由，不填写虚构Scope。拆分、多项合并或移动要在正文解释来源、原身份、目标身份、源码依据与影响。机器对照不会自行选择这些处置。

发布验证先检查 `inventoryDigest` 与导入清单一致，再核对逐条处置，拒绝重复、遗漏、未决和悬空Scope。该摘要防止编辑时意外缩减清单，不是数字签名；验证器不会据卡片内容重新授权读取外部路径，也不证明原始材料未被替换、在线快照最新、理由真实或用户已批准。需要复核来源新鲜度时，使用原显式授权重新运行对照，比对 inputDigest、来源摘要与记录清单，不能只重算摘要掩盖遗漏。来源变化后重新对照并审阅差异，原平台默认、ID大小写和已确认职责不能静默替换。

完成判断不是匹配率：每条来源均有归属、排除或未决说明，关键职责冲突已由源码与明确材料裁决，用户能看懂拟保留、新增、拆分、合并、移动和排除的原因。没有完整源码调查或缺少来源时，如实报告部分结果，不提前写正式知识。
