# DTMP移动客户端取证约定

本文件指导作者调查，不代表解析器已支持所有语言或桥接。以用户确认的平台与模块范围为准，不能由Kotlin后缀推定鸿蒙或iOS适用。

## 查实际责任，不背架构口号

推荐分层是原生页面/适配 → ViewModel → BizModel → Service。当前实现可能仍在OC、Kotlin或ArkTS中做业务判断、参数转换、网络请求和状态管理；按实际方法体记录，不能将“应下沉”当作“已下沉”，也不在产卡时顺手重构代码。

| 边界 | 必须调查的证据 |
| --- | --- |
| IDL与生成绑定 | 声明、生成符号、装配、具体实现和平台调用；名称相似仅是候选 |
| Action/AsyncAction | 真实触发、处理及返回；调用受理、异步完成、最终业务成功分别说明 |
| State/Event | 写入/发布和观察/订阅双方；事件边不冒充同步调用 |
| Bind/Unbind | 实例、订阅、请求scope、取消和迟到回调，离页不等于所有副作用已停止 |
| 原生/共享交接 | 谁准备参数、谁调用后台、谁写状态、谁把结果展示给用户 |
| 语言与构建 | OC selector/category/protocol、OC++混编、Swift桥接；KMP sourceSet/expect/actual；ArkTS组件与平台桥接；构建变体须有真实装配依据 |
| 配置与埋点 | Key声明到读值到分支/曝光；事件触发及参数来源/覆盖，不凭字段名推断链路 |

生成代码用于跨语言映射，不把每个生成文件变成新业务模块。遇到动态派发、不支持语言或缺生成物，报告未解析边界并定向回源；无图边不能证明没有调用者。

## 最小调查闭环

从一个公开功能入口开始，沿关键参数、条件、状态写入和完成信号追踪；同一批事实同时支持功能/API/影响/配置/埋点/恢复。共用组件只追到本模块需要的责任边界，不扩写为整个基础设施域。

仅在项目实际使用 DTMP 时应用本指南。平台、模块和构建变体按确认范围取证；机器证据、源码和人工材料保留来源与版本，既有手册用于定位而不是独立证明。项目特有的配置服务和埋点封装沿真实调用核实，不预设其在所有项目存在。
