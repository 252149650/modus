# 共享检索与降级

## 路由

先复用用户请求、显式路径、对话材料和已经核实的证据。已知源码路径、
接口、符号或知识文件时直达；范围未知时：

1. 读 `modus/knowledge/architecture-overview.md` 选择相关 Domain。
2. 读 Domain `SKILL.md` 选择 Module 与专题。
3. 读完整相关 Module、rule/api/object/state_machine 等正文。
4. 回到当前源码、配置、契约与实际 diff 核验结论。

一次只加载当前判断需要的范围；截断时沿准确标题或源码坐标续读。知识
用于导航，不替代当前源码。

## 普通工作流边界

`using-modus`、context、hooks、update/sync 和公开 status 都不
导入、不读取、不构建 `modus/.cache/init-analysis/`。即使缓存存在也
一样。调用链、影响面、资源效应和拓扑问题通过正文定位后直接核验源码。

只有 `/modus-init` 与 `/modus-reinit` 按统一生命周期同步构建并消费
本轮显式 bundle。不存在公开 graph query 或 refresh 路径。

## 降级

| 状态 | 行为 |
| --- | --- |
| 有正文且可读 | 渐进读取相关正文，再核验源码 |
| 正文缺失或损坏 | 直接检索当前源码和用户材料 |
| CLI 不可用 | 使用宿主的文件读取和搜索能力 |
| 证据冲突 | 并列记录来源，以当前源码和明确用户要求裁决 |
| 关键材料不可读 | 说明影响，不推测其内容 |

缺少 Modus 安装、缓存或索引不阻止普通任务。不要为了“准备环境”创建
模板、运行初始化分析或修改正文。

## 便利接口

`modus context resolve "问题" --scope project-read [--purpose change]`
可返回有界的正文和源码上下文。续查时传入更具体的问题和显式 path；
返回结果不含机器层 freshness 字段。
